# Wave — голосовой чат на PeerJS

Стартовый статический проект для GitHub Pages. В интерфейсе есть создание комнаты, подключение по коду, сетка участников, отключение микрофона и расширенные аудионастройки.

## Что уже реализовано

- Создание комнаты с уникальным кодом `wave-...`.
- Подключение других участников по коду комнаты.
- Голосовые соединения между участниками через PeerJS / WebRTC (mesh-схема, до 6 человек в стартовой версии).
- Переключение микрофона, если браузер видит несколько устройств ввода.
- Шумоподавление, подавление эха и автоматическая регулировка громкости.
- Выбор устройства вывода звука, если это поддерживает браузер.
- Индикатор уровня микрофона, кнопка выключения микрофона, копирование кода комнаты.
- Сохранение аудионастроек в `localStorage`.

## Запуск локально

Самый простой вариант — открыть `index.html` в редакторе VS Code и запустить через расширение Live Server. Микрофон надёжно работает на `localhost` или HTTPS; при открытии как `file://` браузер может заблокировать доступ.

## Публикация на GitHub Pages

1. Создай новый публичный репозиторий на GitHub, например `wave`.
2. Загрузи в корень репозитория файлы `index.html` и `README.md`.
3. Открой **Settings → Pages**.
4. В разделе **Build and deployment** выбери **Deploy from a branch**, ветку `main` и папку `/ (root)`, затем сохрани.
5. После публикации открой выданный адрес `https://ТВОЙ-ЛОГИН.github.io/wave/`.
6. Разреши сайту доступ к микрофону. Для проверки используй два разных браузера или два устройства.

## Важные ограничения

- Это MVP, а не готовый production-сервис. В качестве сигнализации используется доступный PeerJS Cloud по умолчанию. Доступность внешнего сервера зависит от сети и региона.
- WebRTC обычно передаёт аудио напрямую между участниками. В некоторых сетях прямое соединение не устанавливается; для более надёжного подключения понадобится TURN-сервер с собственными учётными данными.
- В текущей mesh-схеме каждый участник соединяется с каждым, поэтому количество участников ограничено шестью. Для больших комнат понадобится SFU-сервер (например, mediasoup или LiveKit) и серверная часть.
- Выбор отдельного динамика зависит от поддержки API браузером и разрешений системы. Если функция не поддерживается, звук будет идти на устройство вывода по умолчанию.
- Шумоподавление и подавление эха — настройки браузерного аудиовхода, а не отдельный ИИ-фильтр Wave. Если браузер или устройство не поддерживают параметр, они могут его проигнорировать.
- Идентификатор комнаты не является паролем. Не публикуй код комнаты в открытом доступе, если разговор должен быть приватным.

## Технологии

- HTML, CSS и JavaScript без сборки.
- [PeerJS](https://peerjs.com/) для сигнализации.
- WebRTC / `getUserMedia()` для аудио.
